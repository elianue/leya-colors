# 二次审核整改说明

## 本次回应：与 Palette Forge 的职责重叠

第二次审核已认可颜色处理的实际用途和 MoonBit 核心实现，要求补充与 Palette Forge 在同一实际使用场景中的复用关系或差异化案例。本次重点回应这一点；源码行数不是差异化依据。

### 可运行的组件约束

参考场景为默认白底、选中粉底的唱片卡片。组件约定只切换背景和选中标记，共用 card.caption.foreground。设计输入提供有序候选：保留原中性色、尝试获批中性色调整、再尝试梅紫色。检查器必须选择一款同时通过两个状态的候选，并保留逐项证据。若设计允许不同状态使用不同文字色，应修改组件约定；统一文字色不是所有界面的强制要求。

这是可运行的参考需求，不是客户采用、真实设计审批或线上部署的证明。示例颜色用于复现，不虚构外部用户。价值是将多处共用 token 的交付约束封装为可测试检查。

### 同任务基线与复用边界

- Palette Forge 可提供色彩生成、主题和对比度测量；示例通过 HEX 交换颜色，不复制其实现，核心库不新增第三方依赖。
- 对同一候选列表和两个背景，比较程序用 Palette Forge check_wcag 独立完成选择，与 Leya 的 select_shared_text_token 得到相同结果：#6B5163。
- 两个引擎都能解决该问题。本项目提供候选偏好、跨状态约束、无匹配状态与逐项证据的公开策略 API，不主张新对比度公式或上游无法实现该策略。
- 单背景 fix_contrast 输出仅用于说明工作流差别，不作为上游多背景能力不足的证明。

### 评委复现入口

在仓库根目录运行：

```sh
moon test
moon test --target js
moon run cmd/shared-token
bash scripts/compare-palette-forge.sh
```

最后一项需要 Bash、Git、网络及 MoonBit。脚本固定 Palette Forge 提交 4ac93f263658d0dad50b673f2d09f6811bbf4486，以工作区使用本仓库源码。程序核验所有候选/背景的比值与通过状态、两种策略选中的 token 及表格中的上游 HEX 输出；不一致即失败。Ubuntu CI 自动运行比较。

具体约束、比较表和边界见 [POSITIONING.md](POSITIONING.md)。共享 token API 尚不包含在 Mooncakes 0.2.0 中；复审请使用仓库源码和上述命令。
